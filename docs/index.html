Why depression.ai

Most AI tools give you answers.
This one does the work — safely.

An agentic AI harness is the layer that lets a language model actually do things: read your files, run commands, edit code, talk to cloud APIs and then check its own work. depression.ai is that layer. Everything else on the internet stops at a chat box; this one is built to be trusted inside a real company or a locked-down government network.

🔒

Security comes first, not last

Every action the agent wants to take is classified by risk before it runs. You approve what matters. Nothing sensitive happens behind your back.

🏠

Runs entirely on your machine

The agent, the tools, the sessions and the logs all live on your computer. Your code and your data never have to leave your network.

🧩

Any model — even a local one

Use a cloud API, your company's private endpoint, or a model running on your own GPU. Same harness, your choice, swap any time with /provider.

👁

You stay in control

Two clear modes: PLAN reads and thinks, BUILD changes things. You choose when the agent is allowed to touch your system.

🔍

It proves its work

The agent re-reads every change, re-runs the affected command and shows you the real output. No "done!" without evidence.

↺

Mistakes are undoable

Snapshots before risky steps, plus /undo, and sessions saved to SQLite so an interrupted run is never lost.

Why this is different from a chatbot

A chatbot can only talk. It cannot open your repo, run your tests, or look at your AWS account. depression.ai wraps the model in a real working environment — tools, permissions, memory and recovery — so it can finish a job and hand you something verifiable. That combination of reasoning + real tools + hard security rules is what makes it genuinely useful instead of just impressive in a demo.

Capabilities

Built for real work, not demos.

Every action is grounded in your actual project — files, tools and infrastructure. No hand-waving, just results you can verify.

Context-aware reasoning

Understands your repo structure, dependencies and conventions before it touches a single line. Context compaction keeps long sessions coherent.

Tool use & execution

Security, by design

Built to be trusted with
things that actually matter.

Giving an AI the ability to run commands on your machine is a serious decision. depression.ai is built around that fact: it assumes the agent should have to earn permission, and it is designed so a person stays in the loop for anything risky.

How it protects you

  • Risk classes — every tool action is labelled safe, medium or dangerous before it runs
  • Approval prompts — medium and dangerous actions ask you first; you can review before saying yes
  • Per-category rules — set what the agent may do to files, the terminal and AWS, separately
  • Read-only AWS guard — a setting that lets the agent inspect your cloud but never change it
  • No hidden secrets — credentials are used, not displayed; API keys and tokens are never printed to the screen
  • Snapshots & undo — changes are reversible, so a bad step is not permanent
  • Nothing leaves your machine unless you point it at a cloud model on purpose

Who this is for

  • Companies with private code that must not be uploaded to a public AI service
  • Government & defence teams working on networks with no outside internet access
  • Banks, healthcare & other regulated industries where data has to stay inside the building
  • Research & labs handling sensitive or unpublished data
  • Any team that needs an audit trail of what the agent did and why

A harness you can justify

A plain chatbot gives you no control over what it does with your data and no record of what happened. depression.ai is the opposite: a self-contained harness where the model, the tools, the permissions and the session history all sit on your side of the fence. You decide which model it uses, which actions it may take, and you can see every step it took in the saved session. That is what makes it usable in an environment where "just trust it" is not an acceptable answer.

Runs on your own machine

Your code stays yours.
Your model can be local too.

depression.ai is not a website you log into. It is a program that runs on your own computer, inside your own network. If you want, the language model itself can run on your hardware as well — so the whole system works with the network cable unplugged.

Install locally

One command installs the harness on your machine. There is no account to create and no data to hand over.

Pick your model

Use a cloud provider, your company's private endpoint, or a model running on your own GPU. Swap any time with /provider and /model.

Keep everything in-house

Your files, your sessions and your logs never leave your machine unless you deliberately choose a cloud model. Even then, only what the task needs is sent.

Architecture

From intent to outcome in three moves.

A clean separation between the agent loop, context management, model providers, permissions and the tool runtime.

Understand

The agent inspects your project and gathers exactly the context it needs.

Plan & act

It decides the next concrete action and executes it with real tools.

Verify & report

Results are checked against reality, then summarized with evidence.

src/agent/ ├── main.py entry point + CLI flags ├── agent/ core reasoning loop ├── context/ context assembly, runtime & compaction ├── llm/ provider adapters + runtime ├── tools/ tool implementations + registry ├── permissions/ risk rules, terminal / fs / aws guards ├── mcp/ Model Context Protocol client + AWS presets ├── plugins/ plugin discovery, loading & registry ├── session/ session lifecycle & recovery ├── storage/ SQLite persistence (sessions, messages, plans…) ├── tui/ Textual terminal UI (widgets, themes, onboarding) ├── cli/ command handling, input & printing ├── config/ layered configuration └── utils/ shared helpers

Sessions, messages, plans, tool outputs and key/value state are persisted to SQLite, so a run survives interruptions and can be resumed with --session <id>.

PLAN agent vs BUILD agent

  • PLAN agent — read & analyze, plan tasks. Designs the approach without mutating anything.
  • BUILD agent — execute tools, modify system. Carries the plan out against real files and infrastructure.
  • Both share one tool system: terminal, filesystem, git, patch, search, web, browser, AWS, MCP, todo & process.
  • Toggle between the two at any time with Ctrl + P.

What the agent actually does

  • Understand an unfamiliar codebase
  • Analyze bugs and failures
  • Plan implementation changes
  • Create and modify files
  • Run commands and tests, then debug failures
  • Review Git changes
  • Use browser automation and search the web
  • Work with MCP tools and tool servers
  • Inspect and operate supported AWS environments
  • Prepare applications for deployment, then verify the result

The execution loop

UnderstandInspectPlanChoose toolExecute Observe resultRe-evaluateContinue / correctVerifyReport

The LLM supplies the reasoning. depression.ai supplies the environment around the model: context, tools, permissions, sessions, execution and recovery. A model with weak reasoning or unreliable tool calling can still produce poor results — quality depends on both parts.
